## Frontmatter reference

Every field a doc's frontmatter block can carry, and what it does.
"Required" means CONTRIBUTING.md's Golden Rules mandate it explicitly
for every doc (not just this scaffold) -- everything else is optional,
standard Docusaurus behavior you reach for only when a doc needs it.

| Field | Required? | What it does |
| --- | --- | --- |
| `title` | Yes | The page's own heading/browser-tab title. Independent of `sidebar_label` -- see "Frontmatter vs. sidebar label" below. |
| `description` | Yes | The `<meta description>` tag and the summary shown in search results (including this site's own local search). |
| `slug` | Yes | The doc's route, explicit even when it matches what Docusaurus would infer from the file path -- so a future rename shows up as an obvious diff instead of silently changing the public URL. |
| `sidebar_position` | Yes | Explicit ordering among sibling docs/categories in the sidebar -- never left to the alphabetical fallback. |
| `sidebar_label` | Only on a folder's index page | Overrides the sidebar row's text for this doc; the page's own `title`/heading are unaffected. See "Frontmatter vs. sidebar label" below. |
| `keywords` | No | Extra SEO keywords beyond `description`, as a string array. Doesn't appear anywhere in the rendered page itself. |
| `id` | No | Overrides the doc's internal id (defaults to its file path). Only matters if something references the doc by id -- this site's sidebar is fully autogenerated, so it rarely comes up. |
| `hide_table_of_contents` | No | Hides the "On this page" TOC column entirely. Used on hub/landing pages built from `PaletteCard`s, since headings inside those cards aren't reliably picked up by the TOC anyway (see `PaletteCard`'s own docstring). |
| `wide_layout` | No | **Project-specific**, not a standard Docusaurus field -- consumed by `src/theme/DocItem/Layout/index.tsx`. Lets the page's content use the width the TOC column would otherwise take, so a `PaletteGrid` can lay out more columns instead of leaving that space empty. Pairs with `hide_table_of_contents: true`. |
| `tags` | No | Doc tags (renders a tag list/tag pages if used) -- a standard Docusaurus feature, not currently used anywhere on this site. |
| `custom_edit_url` | No | Overrides the "Edit this page" link target for just this one doc, instead of the site-wide `editUrl` pattern in `docusaurus.config.ts`. |
| `pagination_next` / `pagination_prev` | No | Overrides which doc the bottom-of-page Next/Previous links point to (or set to `null` to hide one). Defaults to sidebar order. |
| `draft` | No | Excludes the doc from production builds entirely (still visible while running the dev server). |
| `unlisted` | No | Builds the page but leaves it out of the sidebar, search index, and sitemap -- reachable only by a direct link. |
| `last_update` | No | Overrides the auto-derived "last updated by/on" shown under `showLastUpdateTime` -- normally comes from git history. |

### Frontmatter vs. sidebar label

`sidebar_label` and `title` are independent: `sidebar_label` changes
only the sidebar row's text, `title` changes the page's own heading
and browser title -- neither affects the other. If `sidebar_label` is
omitted, the sidebar row falls back to `title`. This page's own
frontmatter above has no `sidebar_label` -- it's a plain leaf doc, not
a folder index page, so its sidebar row falls back to its `title`,
"Sample Page". Compare that with
[section-1.md](../../section-1/section-1.md), the index page one
folder up: it sets `sidebar_label` explicitly, since it's the doc a
Golden Rule requires an index page to have.

## How to add a card

A single card whose whole surface links somewhere -- for one item that
doesn't need its own grid. `PaletteCard`/`PaletteGrid`/`PaletteChip`
are global MDX components (registered in `src/theme/MDXComponents/`),
so no import is needed in the doc itself. `standalone` gives the card
its own bottom margin when it isn't inside a `PaletteGrid` (see that
prop's docstring in `src/components/PaletteCard/index.tsx`).

```mdx
<PaletteCard icon="book" href="/section-1" standalone>
  <h3 class="palette-card-title">Section 1</h3>
  <p class="palette-card-desc">One-line description of where this card leads.</p>
</PaletteCard>
```

<PaletteCard icon="book" href="/section-1" standalone>
  <h3 class="palette-card-title">Section 1</h3>
  <p class="palette-card-desc">One-line description of where this card leads.</p>
</PaletteCard>

`icon` must be one of the names exported by `src/components/PaletteIcon/`.
Add `highlight` to make a card visually stand out from its siblings
(e.g. an AI-assisted feature among plain reference cards) -- a style
variant only, it doesn't change link behavior.

## How to add an image

Plain Markdown image syntax, with a root-relative path into `static/img/`
(Docusaurus serves `static/` at the site root, `img/` in the path maps
to `static/img/`). Always add descriptive alt text -- it's both an
accessibility requirement and what shows if the image fails to load.

```md
![Alt text describing the image](/img/logo.svg)
```

## How to add a separator

Two different things share the name "separator" here -- pick the one
that matches what you're actually breaking up:

- **A visual break between sidebar items** (e.g. grouping a few related
  entries apart from the rest): set `customProps: { "separatorBefore": "Label" }`
  -- on a category's `_category_.json` for a break before a whole
  category, or on a flat doc's own frontmatter as `sidebar_custom_props`
  (same field name either way) for a break before just that one doc.
  Both are rendered by `src/theme/DocSidebarItems/index.tsx`. Never
  hand-edit `sidebars.ts` to force this -- see `sidebars.ts`'s own doc
  comment for why.

  ```json
  // _category_.json -- before a whole category
  { "label": "Reference", "position": 4, "customProps": { "separatorBefore": "More sections" } }
  ```

  ```md
  ---
  sidebar_custom_props: { "separatorBefore": "Separator 1" }
  ---
  ```

  [Section 2](/section-2) is a live example of the frontmatter form --
  its [Page 1](/section-2/page-1) and [Page 2](/section-2/page-2) each
  get their own independent "Separator N" label this way.

- **A break inside a page's own body content** (e.g. between a card
  grid and the prose that follows it): a plain Markdown thematic break.

  ```md
  ---
  ```

## How to add a card grid

Several cards laid out side by side -- wrap them in `PaletteGrid`.
Omit `cols` to auto-fill as many 260px+ columns as fit the width; pass
`cols` to force an exact column count for a fixed, known set of cards
(see `PaletteGrid`'s `cols` docstring for why: auto-fill can wrap
unevenly at in-between viewport widths for a small, fixed set).

```mdx
<PaletteGrid cols={2}>

<PaletteCard icon="quickstart" href="/section-1/sub-section-1">
  <h3 class="palette-card-title">Sub-section 1</h3>
  <p class="palette-card-desc">One-line description of where this card leads.</p>
</PaletteCard>

<PaletteCard icon="book" href="/section-1/sub-section-2">
  <h3 class="palette-card-title">Sub-section 2</h3>
  <p class="palette-card-desc">One-line description of where this card leads.</p>
</PaletteCard>

</PaletteGrid>
```

<PaletteCard icon="quickstart" href="/section-1/sub-section-1">
  <h3 class="palette-card-title">Sub-section 1</h3>
  <p class="palette-card-desc">One-line description of where this card leads.</p>

</PaletteGrid>

For a standalone card immediately followed by a grid (no automatic gap
between them otherwise, since `.palette-group .palette-grid` has no
top margin), wrap both in `<div class="palette-group">...</div>` --
see `editor.md` for a real example of that pairing.

## How to add a sidebar category icon

A different mechanism from everything above -- this one isn't
frontmatter or an MDX component, it's a **hand-picked, label-keyed
lookup** for the collapsed desktop sidebar's icon rail, in
`src/theme/DocSidebar/Desktop/icons.tsx`'s `ICONS_BY_LABEL` map. It
only applies to **top-level** categories (Section 1, not Sub-section 1
inside it), matched against the category's exact `_category_.json`
`"label"` value, case-insensitively. A label with no entry falls back
to a plain dot (`FallbackIcon`) rather than a blank slot.

To add or change one, add (or edit) an entry:

```tsx
// src/theme/DocSidebar/Desktop/icons.tsx
function SectionIcon(): ReactNode {
  return (
    <svg {...iconProps}>
      <polygon points="12 2 2 7 12 12 22 7 12 2" />
      <polyline points="2 17 12 22 22 17" />
      <polyline points="2 12 12 17 22 12" />
    </svg>
  );
}

const ICONS_BY_LABEL: Record<string, () => ReactNode> = {
  // ...existing entries...
  'section 1': SectionIcon,
};
```

This file lives under `src/theme/`, which is synced to every product
branch wholesale (see `.github/workflows/sync-theme.yaml`) -- so each
branch's own category entries end up coexisting in the same shared
file rather than each branch keeping a private copy. That's already
how it works for real branches today (`'editor'` vs `'editor tour'`
are two different branches' labels for the same concept, kept side by
side) -- an unmatched label is harmless, so this causes no conflict,
just some entries from other branches you won't personally use.
